# 합성 GPS 기반 근접 경보 프로토타입 소프트웨어 개발명세서

## 실행 구성

구현 언어는 **C++**, 동형암호 라이브러리는 **OpenFHE**다. 다음 표는 구현 책임과 파일 경계를 정의한다. 각 항목의 운영체제 프로세스 수와 통신 방식은 구현 전에 확정한다.

| 구성 | 구현 책임 |
| --- | --- |
| 합성 GPS 생성기 | 경로와 생성 설정을 입력받아 노드별 GPS 관측 파일, 실험용 참값 파일을 생성한다. |
| 피해자 노드 | 피해자 관측 파일을 읽는 C++ 프로그램이다. 관측 위치를 격자화·암호화하여 서버에 전달하고, 반환된 1km 위치 공개 플래그를 개인키로 복호화한다. 플래그가 1이면 해당 프레임의 피해자 관측 위치를 평문으로 서버에 보낸다. |
| 가해자 노드 입력 | 가해자 관측 파일과 이를 시각 순으로 읽어 위치를 제공하는 재생 기능이다. |
| 중앙 서버 및 관제 화면 | 가해자 평문 위치와 피해자 위치 암호문으로 암호화된 1km 위치 공개 플래그를 계산한다. 피해자 평문 위치를 받으면 같은 프레임의 두 평문 위치로 100m 긴급 여부를 판정한다. 관제 화면에는 서버가 받은 평문 위치와 처리 결과를 표시한다. |

평가 서버는 피해자 관측 파일과 개인키를 보유하지 않는다. 참값 파일과 독립적인 평문 기준 계산은 시연 검증에서 사용한다. 관제는 피해자 노드가 공개한 위치와 서버의 100m 판정으로 시연 단계를 표시한다. [팀 2 제안서 6–8쪽](../보안프로젝트설계_Team2_proposal.pdf#page=6)

## 데이터 계약 초안

| 파일 또는 메시지 | 필드 및 단위 |

| victim_gps.csv / offender_gps.csv | `t_ms,lat_deg,lon_deg`. 시나리오 시작부터의 경과 시간과 GPS 관측 위·경도 |
| truth.csv | `t_ms,v_e_m,v_n_m,a_e_m,a_n_m,d_true_m`. 잡음 없는 두 위치와 동시각 참거리 |
| 서버용 피해자 입력 | `t_ms`, 격자 좌표의 암호문 |
| 서버에서 피해자로 반환 | `t_ms`, `Enc(within_1km)` |
| 피해자에서 서버로 위치 공개 시 전송 | `t_ms`, 해당 프레임의 평문 관측 좌표 `lat_deg,lon_deg` |

파일 재생에서는 두 CSV의 동일한 `t_ms` 행을 한 프레임으로 사용한다. 합성 생성기는 공통 시각열을 만들며, 재생기는 입력 시간 불일치를 시나리오 오류로 표시한다. GPS는 수신기에서 나온 위·경도 관측값 수준으로 모사한다.

## 합성 GPS 생성 알고리즘

### 경로를 시간별 참좌표로 변환

1. 독립적으로 작성한 웨이포인트 또는 사용권을 확인한 길찾기 결과에서 노드별 WGS84 좌표열을 읽는다. 두 노드에 같은 원점을 적용하여 로컬 동쪽·북쪽 평면 좌표 `(E,N)`로 변환한다. 좁은 시연 구역에서 기준점 주변의 거리를 미터 단위로 계산하도록 범위를 잡는다. [PROJ 로컬 위상좌표 변환](https://proj.org/en/stable/operations/conversions/topocentric.html)
2. 연속 중복점을 제거하고 선분 길이의 누적합 `L[i]`를 계산한다. 설정된 출발 전에는 첫 점에 머물고, 이후 시간 간격별 이동 거리를 `s(t)`에 더한다. 일정한 속도 `v`에서는 출발 후 `s(t) = v × (t − t_start)`다. 정차 중 속도는 0으로 두고 경로 끝이나 정지 노드에서는 위치를 고정한다.
3. `L[i] ≤ s < L[i+1]`인 선분을 찾아 `α = (s − L[i]) / (L[i+1] − L[i])`로 두 점을 선형 보간한다. 마지막 점에서는 보간 없이 끝점을 사용한다. 두 노드 모두 `t = 0, Δt, 2Δt, …`에 샘플링한다.
4. 같은 시각에서 두 참좌표의 유클리드 거리를 구해 `truth.csv`에 쓴다. 참거리가 의도한 시나리오를 충족하는지 최소 거리, 기준 안 진입 시각, 기준 안 체류 구간으로 확인한다.

### GPS 관측 오차 주입

각 노드와 각 축의 오차 `e[k]`를 아래 식으로 모델링한다. 축별·노드별 난수 스트림을 구분한다. `σ`는 한 축의 오차 표준편차로 단위는 미터다. `ρ`는 연속 표본 오차의 상관을 제어한다.

~~~
e[0] = σ × Z[0]
e[k] = ρ × e[k−1] + σ × sqrt(1 − ρ²) × Z[k]
관측 위치[k] = 참 위치[k] + (e_E[k], e_N[k])
~~~

`Z[k]`는 독립 표준정규 난수다. `σ=0`이면 무잡음, `ρ=0`이면 표본 간 독립 오차다. `ρ>0`이면 인접한 오차가 비슷한 방향으로 남는 현상을 시험할 수 있다. 이 모델의 수치는 비교 실험용으로 정하며, 실제 수신기의 정확도는 현장 데이터로 따로 검증해야 한다. 잡음을 넣은 평면 좌표는 WGS84 위·경도로 역변환해 GPS 파일에 기록한다.

초기 파일럿 후보는 **1초 간격**, 축별 `σ=0, 3, 10m`, 독립 오차 `ρ=0`와 시간상관 오차 `ρ=0.8`이다. 먼저 같은 경로와 동일한 정규 난수열로 노이즈 크기만 바꾸고, 다음에는 같은 크기에서 상관만 바꾼다. 실행 설정과 시드, 생성된 CSV를 함께 보관해 발표 데이터를 그대로 재생할 수 있게 한다. 반복 실험에서는 독립 시드를 사용한다.

## 1km 위치 공개와 100m 긴급 판정

1. 서버와 피해자 노드는 관측 위·경도를 공통 평면 좌표계와 동일한 격자 변환 규칙으로 정수 좌표로 변환한다. 피해자 노드는 자신의 격자 좌표를 암호화해 `t_ms`와 함께 전송한다.
2. 서버는 매 프레임의 가해자 평문 격자 좌표와 피해자 위치 암호문으로 격자 제곱거리 `D²=(xᵥ−xₐ)²+(yᵥ−yₐ)²`를 암호문 상태에서 계산한다. 1,000m에 해당하는 정수 임계값과 비교해 `Enc(within_1km)`을 돌려준다.
3. 피해자 노드는 위치 공개 플래그를 복호화한다. 플래그가 1이면 그 프레임을 암호화할 때 사용한 관측 위·경도를 `t_ms`와 함께 평문으로 전송한다. 플래그가 0이면 위치를 보내지 않는다.
4. 서버는 수신한 피해자 관측 좌표를 같은 규칙으로 격자화하고, 같은 `t_ms`의 가해자 격자 좌표와 평문 제곱거리를 계산한다. 그 값이 100m에 해당하는 정수 임계값 이하면 해당 프레임을 긴급으로 표시한다. 이 계산에는 해당 프레임에 공개된 피해자 위치가 필요하다. 1km 밖에서 안으로 바뀐 프레임에는 경찰의 피해자 방향 출동과 보호관찰관의 가해자 방향 출동을 표시한다. 진입 프레임이 100m 이내라면 긴급도 함께 표시한다.

격자 한 칸이 g미터이고 격자 칸 단위의 정수 제곱거리가 D²라면, 반경 R미터의 판정은 D² ≤ floor((R/g)²)로 나타낸다. 경계 시험은 1,000m와 100m를 사용하며 경계값을 포함한다. OpenFHE 암호 방식·파라미터, 격자 간격·정수 변환 규칙, 운영 경보 여유 거리와 평가 주기는 미정이다. 1초는 GPS 파일의 시험 표본 간격이다. 1km 대응은 시연 화면에 표시하며 실제 외부 연계는 구현 범위 미정이다.

### OpenFHE 1km 비교 구현 후보

1km 위치 공개 판정의 암호문 비교는 아래의 OpenFHE 동형연산으로 구현할 수 있다.

- **격자 정수 비교.** OpenFHE BinFHE에서 제곱거리를 고정 길이의 암호화된 비트열로 계산하고, 공개 임계값의 비트열과 비교한다. 상위 비트부터 두 수의 관계를 갱신하는 회로를 Boolean 게이트로 구현할 수 있다. 비트 폭을 정할 때 좌표 차의 부호와 두 제곱의 합이 표현 범위를 넘지 않도록 한다. 등호까지 포함하는 비교를 구현하면 같은 격자 입력에 대해 평문 정수 비교와 일치하는 결과를 목표로 검증할 수 있다. [OpenFHE BinFHE Boolean 게이트 예제](https://github.com/openfheorg/openfhe-development/blob/main/src/binfhe/examples/boolean.cpp)
- **CKKS와 FHEW 간 방식 전환.** OpenFHE의 `EvalCompareSwitchPrecompute`와 `EvalCompareSchemeSwitching`을 사용해 비교를 수행할 수 있다. 후자는 CKKS 암호문 두 개를 받아 부호 비교 결과를 CKKS 암호문으로 반환하므로 공개 임계값도 입력 형식에 맞추어 암호화한다. 이 후보는 스케일, 비교할 값의 범위와 경계 근처의 수치 오차를 확인해야 한다. [OpenFHE 비교 API](https://openfhe-development.readthedocs.io/en/latest/api/classlbcrypto_1_1CryptoContextImpl.html) · [공식 방식 전환 예제](https://github.com/openfheorg/openfhe-development/blob/main/src/pke/examples/scheme-switching.cpp)

격자 정수의 경계값을 정확히 처리하는 요구사항을 기준으로 첫 검증 후보는 BinFHE 비트 비교다. 제곱거리 계산까지 포함한 성능은 구현 후 측정한다. 1km 암호 비교기와 100m 평문 비교기를 각각 단위 시험한다. 각 비교기에 해당 임계값보다 1 작은 값, 같은 값, 1 큰 값을 넣었을 때 차례로 1, 1, 0을 반환해야 한다.

## 실험 평가

| 비교 | 입력과 기준 | 측정·해석 |
| --- | --- | --- |
| 1km 암호 계산 검증 | 동일한 관측 격자 좌표와 1km 정수 임계값을 평문 C++ 기준 계산과 OpenFHE에 넣는다. | 평문 기준과 복호화한 위치 공개 플래그의 불일치 건수. 발견하면 좌표 부호, 단위 변환, 정수 범위와 비교 구현을 먼저 점검한다. |
| 100m 긴급 판정 검증 | 피해자 위치를 공개한 프레임에서 서버의 평문 판정을 같은 격자 입력으로 구한 100m 기준값과 비교한다. | 긴급 표시 불일치 건수와 공개 좌표의 프레임 일치 여부를 확인한다. 1km 밖인 프레임에서는 피해자 위치 수신이나 긴급 표시가 발생하면 오류로 집계한다. |
| GPS 오차 영향 | 노이즈를 넣기 전 같은 시각의 참좌표에서 구한 1,000m와 100m 플래그를 기준으로 삼는다. 무잡음 격자 결과와 유잡음 격자 결과도 따로 비교한다. | 단계별 오판 건수와 첫 진입 판정 시각. 무잡음에서도 차이가 나면 격자화 영향을 먼저 확인한다. |
| 시연 동작과 처리 시간 | 피해자 노드부터 관제 표시까지 시나리오를 재생한다. | 프레임별 OpenFHE 처리 시간과 경보 표시까지의 시간. 시연은 계산 완료 프레임을 순서대로 표시해 입력 시간과 실제 처리 시간을 구분한다. |
