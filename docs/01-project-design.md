# 동형암호 기반 접근금지 근접 경보 프로토타입 설계

## 프로토타입에서 보여줄 것

합성 GPS 좌표를 기록한 파일 두 개로 피해자와 가해자의 이동을 재생한다. 관제 담당자는 화면에서 가해자 위치와 시나리오 진행 상황을 본다. 중앙 서버는 가해자의 평문 좌표와 피해자의 암호화된 좌표로 제곱거리와 근접 여부를 계산한다. C++ 피해자 노드는 1km 위치 공개 플래그와 100m 긴급 표시 플래그를 복호화한다. 1km 진입 시 피해자 위치가 관제센터에 전달된다. 경찰은 피해자 쪽으로, 관제센터의 보호관찰관은 가해자 쪽으로 출동한다. 100m 이내는 화면의 긴급 단계로 표시한다. [팀 2 제안서 4–8쪽](../보안프로젝트설계_Team2_proposal.pdf#page=4)

피해자 쪽 구현물은 GPS 파일을 읽어 암호화·복호화를 수행하는 C++ 실행 프로그램이다. 가해자 쪽 위치추적 장치는 정해진 시간 순서대로 읽는 파일로 모사한다. 관제센터가 보는 화면이 사용자 인터페이스이며, 첫 시연 UI로는 로컬 웹 대시보드를 제안한다. OpenFHE 연산과 파일 재생은 C++ 쪽에서 수행한다. 시연 화면은 1km 진입 시 두 대응 방향을 표시하고, 100m 이내에서 긴급 표시를 추가한다. 실제 경찰 통보·출동 시스템과의 연계는 구현 범위 미정으로 유지한다.

## 길찾기 경로를 GPS 파일로 만들 수 있는가

**경로의 좌표열을 얻어 시간별 GPS 좌표로 변환하는 것은 기술적으로 가능하다.** Google Maps Platform의 Routes API는 출발점, 도착점과 선택적 경유점을 받아 경로를 계산하고 `routes.polyline.encodedPolyline`으로 경로 형상을 반환한다. 다만 Routes API 정책은 지도 콘텐츠의 서비스 외부 반출·저장과 이를 기반으로 한 파생 콘텐츠 생성을 제한한다. Google 경로를 저장하고 노이즈를 더해 재사용 가능한 실험 CSV로 만드는 방식은 해당 사용권이 확인된 경우에 채택한다. Google Maps 웹에서 길찾기 화면을 수동으로 따라 좌표를 옮기는 방식에도 별도의 이용 조건이 적용된다. [Google Routes API 요청 명세](https://developers.google.com/maps/documentation/routes/reference/rest/v2/TopLevel/computeRoutes) · [Routes API 정책](https://developers.google.com/maps/documentation/routes/policies) · [Google Maps 최종 사용자 약관](https://maps.google.com/help/terms_maps/)

시연용 경로의 기본안은 **지도에서 출발점·도착점과 선택적 경유점을 찍고, OpenStreetMap 데이터 기반 OSRM에서 경로를 구하는 방식**이다. OSRM Route API에서 `geometries=geojson&overview=full`로 요청하면 경로의 전체 좌표열을 얻을 수 있다. OSRM 인스턴스는 원하는 이동 방식에 맞는 프로필로 구축된 것을 사용한다. 지도·경로의 출처를 표시하고 보관·배포 시 OpenStreetMap 라이선스를 따른다. 경계값 실험은 좌표를 직접 정의한 합성 경로로 구성해 정확한 거리와 시점을 재현한다. [OSRM Route API 명세](https://project-osrm.org/docs/v5.24.0/api/#route-service) · [OpenStreetMap 저작권 및 라이선스](https://www.openstreetmap.org/copyright)

## 실험 시나리오 초안

사람 간 거리로 현재 프레임의 단계를 결정한다. 두 경계는 모두 포함한다.

| 두 사람 사이의 거리 | 관제센터 동작 |
| --- | --- |
| 1km 초과 | 평상시 감시를 유지한다. 피해자의 현재 위치는 공개되지 않는다. |
| 100m 초과, 1km 이하 | 관제센터가 피해자 위치를 표시한다. 1km 경계에 진입한 프레임에서 경찰은 피해자 쪽으로, 보호관찰관은 가해자 쪽으로 출동하는 것으로 시연한다. |
| 100m 이하 | 1km 진입 시 시작된 대응에 긴급 표시를 추가한다. 첫 진입 프레임이 100m 이내라면 두 대응 방향과 긴급 표시를 함께 표시한다. |

아래 거리들은 시연 입력 예시다. 경계값 검증은 여유 거리 0m로 수행하고, 운영 목적의 여유 거리는 미정으로 둔다.

| 시나리오 | 경로 구성 | 화면에서 볼 것 |
| --- | --- | --- |
| 계속 1km 밖 | 피해자는 고정하고 가해자는 최소 1.5km 떨어진 경로를 이동시킨다. 노이즈 0으로 시작한다. | 평상시 감시가 유지되고 피해자 현재 위치가 표시되지 않는다. |
| 1km만 진입 | 가해자의 최단 참거리를 300m로 둔다. | 피해자 위치를 공개하고 두 대응 방향을 표시한다. 긴급 표시는 발생하지 않는다. |
| 1km와 100m 모두 진입 | 가해자는 1.2km 이상에서 시작해 약 50m까지 접근한 뒤 멀어진다. | 1km에서 위치 공개와 양쪽 출동, 100m에서 긴급 표시를 확인한다. |
| 같은 길을 다른 시간에 통과 | 두 노드가 교차하되 통과 시각을 다르게 둔다. 같은 시각의 거리가 1km를 넘는지 참값으로 확인한다. | 지도상 경로가 겹쳐도 평상시 감시가 유지된다. |
| 경계 근처와 노이즈 | 참거리가 95m·100m·105m, 995m·1,000m·1,005m인 시험점과 두 경계를 지나는 경로를 사용한다. | 각 경계의 암호화 판정을 같은 격자 입력의 평문 판정과 비교한다. 참값과 달라지는 구간에서는 GPS·격자화 오차를 확인한다. |
| 실제 도로 형상 재생 | 공개 지도 기반 길찾기로 좌표열을 생성한다. 시작 시각과 속도를 조정한 뒤 두 노드의 최소 동시 거리를 계산해 시나리오를 분류한다. | 곡선과 교차로를 포함한 경로를 재생하며 지도 이동과 경보 타임라인을 함께 본다. |

## 거리와 시간이 확인되는 시연 입력 예시

공통 평면에서 위치 단위는 미터, 시간 단위는 초다. 아래 예시로 노이즈가 없는 참좌표부터 생성한 뒤 동일한 시각열에 노이즈를 주입한다. 지도 시연용 좌표는 선택한 공통 원점을 기준으로 위·경도로 변환한다.

- **두 단계 접근**은 피해자를 (0, 0)에 고정하고 가해자를 (50, 1,200)에서 (50, −1,200)까지 초당 10m로 직진시킨다. 1초마다 샘플링하면 참거리 기준으로 21–219초에 1km 이내, 112–128초에 100m 이내다. 최단거리는 120초의 50m다. 실제 표시 시점은 격자화와 OpenFHE 판정으로 확인한다.
- **1km 대응만 발생**하는 예시는 같은 경로의 동쪽 좌표를 300m로 바꾼다. 가해자는 1km 이내로 들어와 양쪽 출동이 시작되며, 최단거리가 300m이므로 긴급 표시는 발생하지 않는다.
- **다른 시간에 교차**는 가해자 위치를 (−1,500 + 15t, 0), 피해자 위치를 (0, −3,300 + 15t)로 두고 0–250초를 재생한다. 통과 시각은 각각 100초와 220초다. 같은 시각의 최단거리는 약 1,273m다.

## 발표에서 보여주는 순서

1. 두 단계 접근 시나리오를 1km 밖에서 시작한다. 관제 화면에는 가해자 현재 위치와 재생 시각이 표시된다.
2. 1km 이내에 처음 들어오면 **피해자 노드 복호화 → 피해자 위치 수신 → 경찰은 피해자 쪽, 보호관찰관은 가해자 쪽으로 출동**하는 흐름을 보여준다.
3. 100m 이내로 들어오면 같은 관제 화면에 **긴급**을 추가로 표시한다.
4. 1km만 진입하는 시나리오와 경계 노이즈 시나리오를 재생한다. 발표용 검증 그래프에서 두 기준선과 참거리, 관측 격자 판정을 비교한다.
